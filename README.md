# 大话西游页签多开器（页签式 Java 游戏窗口管理器）

一个用纯 Win32 C 编写的浏览器式页签多开器：把多个大话西游客户端窗口"贴靠"进一个带页签条的容器里，像浏览器标签页一样切换、改名、收起、掉线重开。**不注入、不修改游戏进程，纯窗口管理。**

![架构](https://img.shields.io/badge/arch-%E9%9B%B6%20SetParent-blue) ![lang](https://img.shields.io/badge/lang-Win32%20C-red) ![size](https://img.shields.io/badge/exe-40KB-green)

## 功能

- **页签条兼标题栏**：自绘 32px 深色页签条，整页签按状态着色（🟢 在线 / 🟡 启动中 / ⚪ 掉线）
- **页签操作**：左键切换/收编 · 中键收起 · 悬停显示 × · 双击改名（ini 持久化）
- **开新号**：`+` 或 `Ctrl+T`，目录隔离启动（exe 副本 + junction 共享资源，绕过单实例锁）
- **掉线处理**：掉线号页签变灰保留，点击原槽位重开；收编前关掉的号自动恢复
- **自动切换**：关闭某号自动切到最近使用过的号
- **托盘**：× 最小化到托盘，右键菜单各号直切
- **快捷键**：`Ctrl+1..6` 切换 · `Ctrl+T` 开新号 · `Ctrl+W` 收起当前号 · `Ctrl+Shift+P` 诊断日志
- **多实例**：最多 8 个多开器实例，每个管理 6 个游戏；快捷键自动作用于"当前活动窗口所属"的实例
- **零动画**：切换 = 一次 `ShowWindow`

## 构建

```
gcc -O2 -s -municode -mwindows src/duokai_tab.c -o duokai_tab.exe -lgdi32 -luser32 -lshell32 -lole32
```

- 任何 MinGW-w64 均可（WinLibs GCC 16 测试通过）
- 无第三方依赖，产物约 40KB，单文件绿色便携

## 使用

1. 把 `duokai_tab.exe` 放进游戏主目录（与 `大话西游.exe` 同目录）
2. 运行 → 点 `+` 开新号 → 登录游戏 → 点对应页签收编
3. 也可以手动多开游戏，点页签会自动"收编"游离的游戏窗口

## 价值定位（与同类工具对比）

市面上私服多开器（含不少收费版）常见三类硬伤，本项目针对性解决：

| 问题 | 常见同类工具 | 本项目 |
|---|---|---|
| **线程/句柄泄漏** | 旧版第三方多开器长期运行句柄/线程数持续暴涨，数小时后系统卡顿甚至拖垮游戏 | 纯 Win32 C、零运行时，切换仅一次 `ShowWindow`，句柄数恒定 |
| **跨游戏通用性** | 多为"特定游戏特定写法"，换个私服/换皮客户端就失效 | 收编式架构（标题匹配 + `OWN_PROP` 归属标记）不挑游戏，各私服大话2客户端均可套用 |
| **切换精准度** | 跨进程抢前台普遍处理粗糙：切不过去、焦点丢失、被游戏异步抢回 | 三层置前权限（直接试探 / Alt 脉冲 / 双线程挂接）+ 80ms 前台守护，逐个实测闭环 |

**架构旁证**：官方怀旧服启动器（大话西游3怀旧版.exe，Jar2Exe 打包）用的是"同一 JVM 内 JavaFX 自绘页签 + JNA 调 user32"的同进程方案，天然规避跨进程置前问题——而独立多开器管的是**别人的进程**，必须正面解决上述第 3 条。这正是本项目踩坑清单里坑 3/4/5 的由来，也是它区别于"照抄官方思路"的价值所在。

## 移植性

单文件 exe，只依赖系统 DLL（msvcrt/user32/gdi32/shell32），**拷到其他 Windows 10/11 电脑可直接运行**。前提只有一条：目标机器装有大话西游客户端。注意：exe 未签名，首次运行可能被 SmartScreen/杀软提示，放行即可。

## 踩坑全集（重点！给做同类工具的人）

这套东西踩过的坑，每一个都花了真金白银的调试时间：

### 1. SetParent 是单行道 ❌

把 Java AWT 窗口（`SunAwtToolkit`）`SetParent` 进容器后，**任何脱父子事件**（恢复、关闭容器、甚至切换显示器）都会让 AWT 重建原生窗口——你拿到的是一个白屏空壳。实验（`experiments/embed_test3*.c`）证明了"嵌入"路线对 AWT 窗口判死刑。

**正确姿势：零 SetParent**。游戏永远是顶层窗口，只用 `SetWindowPos` 平移贴靠进容器客户区，容器在 z 序上压在游戏下方；页签切换用 `SW_HIDE/SW_SHOW`（对顶层窗口隐藏不会触发 AWT 重建）。

### 2. AWT 会"跑位" 🏃

AWT 缓存了窗口坐标，隐藏的窗口被它挪回原位的时机不可控。所以容器**只首次定位**（`g_framePlaced`），永远"游戏迁就容器"，不要让容器跟着游戏跑。

### 3. 隐藏前台窗口 = 激活乱流 💥

切换页签时如果**先隐藏旧号（它正是前台窗口）**，系统会被迫自动激活 z 序里"下一个"窗口——落到谁身上不可控，表现为容器被最小化、活动窗口跳到别的程序。叠加 `AttachThreadInput` 在"濒死线程"上挂接，与 AWT 纠缠出各种怪状态。

**正确顺序：先置前新号（旧号还健康）→ 再隐藏旧号**（非前台窗口的隐藏不触发任何激活行为）。

### 4. 跨进程置前的三层权限 🎯

快捷键切换时你的进程**没有前台权限**（输入被发给了游戏进程），`SetForegroundWindow` 会被静默拒绝，而且：

- 目标窗口和前台窗口是**两个不同的 Java 进程线程**，`AttachThreadInput` 只挂前台线程不够，**必须把目标线程也挂进同一输入队列**
- 即使当场成功，游戏 AWT 线程对"失活/被隐藏"还有**延迟反应**会异步抢回前台 → 需要一个 80ms 守护定时器被抢就夺回（0.4s 上限）
- 另一个经典解法是 **Alt 键脉冲**（`keybd_event(VK_MENU,...)`）解锁前台锁——本项目两层都用上了

### 5. RegisterHotKey 是全局唯一的 🔑

`Ctrl+1` 全系统只能被**一个**进程注册，多实例方案必然出现"转发中继"。**正确姿势：每个实例装自己的 `WH_KEYBOARD_LL` 钩子**，各自判断前台窗口归属（`GetPropW` 归属标记），归我就执行+吞键，不归我放行。零转发、零通信。

### 6. 收编要用窗口属性做归属标记 🏷️

`SetPropW(hwnd, L"YunHaiOwned", hFrame)`——既防多实例重复收编同一个游戏，又让钩子能查出"这个游戏归哪个实例管"。

### 7. Java 游戏的"单实例锁"用目录隔离绕过 🔒

exe 副本到 `_instances\NN` + junction 共享资源目录 + 工作目录指向游戏主目录。注意 **pid 记住的是 Jar2Exe 启动器**，JVM 是脱钩子进程——判死活要看窗口在不在，不是看 pid。

### 8. 弹窗被游戏挡住的真凶：归属层级 🪟

owned window 跟随 owner 的 z 序/层级。把弹窗的 `hwndOwner` 设为 NULL + `MB_TOPMOST|MB_SETFOREGROUND`，它就彻底脱离容器层级，钉扎逻辑压不到它。
